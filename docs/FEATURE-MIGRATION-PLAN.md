# MasterTerm 功能迁移计划

> 这是已完成的历史迁移记录。当前新增功能和优化不再写入本文件，统一维护在 [当前任务计划](MASTERTERM-TASK-PLAN.md) 中。

## 范围与原则

目标是补齐原 `masterssh` 中仍有价值、且适合 Win32 + WebView2 架构的功能。

不在计划内：

- 工作区卡片拆出为独立窗口。
- 启动时恢复或指定默认工作区卡片布局。
- Telnet、远程桌面、数据库等原项目也不支持的协议。

每个阶段完成时必须：构建 `MasterTerm` 及原生测试目标、运行相关测试、更新本文件的状态，并单独提交 Git。

## 阶段 8：高价值新功能（已完成）

- [x] SSH 端口转发：本地转发 / 远程转发隧道，支持多隧道并发与非阻塞中继，
      随 SSH 会话管理（`tunnel.create` / `tunnel.list` / `tunnel.stop`）。
- [x] 终端搜索：Ctrl+F 打开搜索条，Enter / Shift+Enter 上下跳转，Esc 关闭。
- [x] 可配置 SSH 保活间隔（0–3600 秒）与自动重连（开关 + 次数上限）。
- [x] 本地终端：基于 Windows ConPTY 的本地 shell 会话，与 SSH / 串口共用
      终端与输入输出消息流；子进程标准句柄由 ConPTY 提供，不继承宿主控制台。
- [x] 系统托盘：关闭 / 最小化隐藏到托盘，后台会话保持连接；托盘菜单提供
      显示主窗口与退出；会话结束（注销 / 关机）时干净退出。
- [x] 命令收藏：终端工具栏「☆ 收藏」管理常用命令，支持新建 / 编辑 / 删除 /
      保存当前输入，一键发送到当前会话，多行命令自动补回车；数据存于本机
      localStorage。
- [x] 原生测试目标在 Release 构建下保持断言启用（`/UNDEBUG`），保证 Release
      回归测试真实执行检查。

> 最近完成：阶段 8 已实现。5 个原生测试目标与全屏终端回归脚本全部通过；
> 本地终端经真实 cmd 会话验证（回显、退出、输出进 pty）；命令收藏经
> WebView2 远程调试端到端验证（添加、发送、持久化）。

## 阶段 1：配置可迁移与可恢复

- [x] 导出服务器与工作区到 JSON；默认剥离密码、私钥内容和 Credential Manager 凭据。
- [x] 导入 JSON：先校验结构，再显示新增/更新/跳过摘要，由用户确认后写入。
- [x] 自动备份当前配置，并提供从备份恢复的入口。
- [x] 兼容已有 `%APPDATA%\MasterSSH\MasterSSH.json` 的字段。
- [x] 使用现有原生配置测试验证原子替换与损坏文件读取保护；合并流程需用户验收。

> 最近完成：第 1 阶段已实现。导入按“连接类型 + 地址 + 端口”合并，写入前自动生成脱敏备份；密码仍由 Windows Credential Manager 管理，不进入导出文件。

## 阶段 2：连接管理效率（已完成）

- [x] 连接列表支持 Ctrl/Shift 多选与清晰的选中样式。
- [x] 批量修改工作区、标签颜色和图标；批量删除前确认。
- [x] 服务器编辑对话框提供颜色和图标选择，并在卡片上展示。
- [x] 空白区域右键菜单提供新建、导入、导出入口。

## 阶段 3：SFTP 浏览与传输可靠性

- [x] 远程和本机目录支持名称、大小、时间、权限和所有者列排序；排序只作用于当前目录。
- [x] 支持当前目录名称过滤，不触发远端重新读取。
- [x] 传输失败按有限次数自动重试；最多自动重试 2 次，最终失败后继续队列并报告错误。
- [x] 批量任务统一冲突策略；同一批次只询问一次，跳过/重命名/覆盖应用于对应冲突项。
- [x] 保留批量任务中每一项的成功、跳过、取消和最终失败结果；状态栏显示最近 12 项。
- [x] 为 Worker 输出解析和重试状态增加测试；独立解析 `P`/`D` 进度行并覆盖非法、分片和 CRLF 输入。

## 阶段 4：资源管理器互操作（不纳入范围）

- [—] 使用 Win32 虚拟文件拖放，将远端选中项拖到 Windows 资源管理器。
- [—] 只有在资源管理器实际接收后才启动下载，避免误触发。
- [—] 支持文件夹递归下载、多选和取消。
- [—] 失败时任务进入传输中心，而不是静默丢失。

- [x] 右键“选择程序打开”。
- [—] 编辑副本列表：按产品需求取消，不再提供独立入口。
- [x] 支持立即同步、重试同步、停止跟踪、打开本地副本目录。
- [x] 传输中心聚合上传、下载、拖放与编辑同步任务，支持过滤、取消和重试。
- [x] 为自动同步的覆盖行为提供可配置冲突保护。

> 最近完成：第 5 阶段已实现。远程文件编辑副本与传输中心统一管理，支持立即同步、重试、停止跟踪与打开本地副本目录；传输中心内的编辑同步任务可直接控制会话状态。

## 阶段 6：终端效率与诊断（已完成）

- [x] 断线/错误标签提供“重新连接”。
- [x] Ctrl+滚轮调整当前终端字号，并支持保存为默认值。
- [x] 补充光标形状和闪烁设置。
- [x] 增加终端诊断窗口：原始字节、UTF-8 解码结果、行列与缓冲区信息。

> 最近完成：第 6 阶段已实现。终端回归脚本 `tests/fullscreen-terminal-regression.js` 在 Node 下直接驱动内置 xterm 引擎，所有全屏场景均通过。

## 阶段 7：监控、安全与恢复

- [x] 顶部监控增加短期 CPU 曲线；曲线按 500ms 采样并保留 15 秒，内存统一使用 GB 显示。
- [x] 顶部监控可查看各磁盘分区详情（悬停“磁盘”指标显示挂载点、使用率和容量）。
- [x] 已知主机管理：查看、移除、重新确认主机指纹。
- [x] 可选保存会话恢复信息（连接配置和终端标签，不保存密码或命令内容）。
- [x] 为监控与主机密钥数据的异常输入增加测试（监控采样解析与 known_hosts 解析均为独立纯函数，覆盖损坏、非数字、CRLF、越界数字与二进制垃圾输入）。

> 最近完成：第 7 阶段已实现。监控采样与 known_hosts 解析抽为可测试纯函数并接入原生测试目标，异常输入用例全部通过。
