# MasterTerm 后续任务计划

更新时间：2026-09-15
计划基线版本：`0.1.127`
当前分支：`main`

本文件是后续开发的执行顺序和验收依据。除非用户明确调整范围，否则按阶段顺序
推进；每完成一个任务，都要同步更新本文件的状态、实现摘要、测试结果和剩余问题。

## 当前基线

- 主程序架构：Win32 + WebView2 + 标准 C++ + libssh2。
- 已具备：SSH、SFTP、串口、本地 ConPTY、RDP、多标签、分屏、工作区、远程编辑、
  传输中心、监控、云同步、自动更新、Agent/CLI 和 NSIS 安装包。
- 当前自动化测试：21 项 CTest，包含终端、分屏、RDP 切换、原生遮罩、进程生命周期、
  侧边栏自动隐藏、日志脱敏、诊断日志、DPAPI、云同步、传输队列、目录续传和真实
  WebView2 端到端测试，以及冲突策略、传输中心和特殊路径回归。
- 当前主要风险：真实 WebView2/RDP/SFTP 端到端测试不足；云同步仍需加强安全和冲突处理；
  传输队列和退出生命周期还需要更多真实环境验证。

## 每个任务的固定执行流程

1. 修改前检查 `git status --short`，保留用户已有改动。
2. 先写清楚影响范围和验收标准，再修改代码。
3. 使用 `apply_patch` 修改源码；不重新引入 Qt/Qt6，不改变既定产品边界。
4. 按风险运行 `node --check`、`git diff --check`、CMake 构建、CTest 和专项测试。
5. 真实环境需要用户操作时，将任务标记为“待验收”，不要把自动化通过当作最终完成。
6. 每次正式发布都递增版本号，并同时更新 README、ZIP/NSIS 包和更新清单。
7. 未经用户明确要求，不自动推送 Gitee、更新服务器或安装到用户系统。

## 暂不纳入范围

- 新增 Telnet、数据库等没有稳定基础的新协议；
- 工作区独立浮动窗口或启动时恢复工作区卡片布局；
- 将远程文件拖入资源管理器后的虚拟文件拖放方案；
- 重新引入 Qt、Qt6 或 Qt 动态库。
